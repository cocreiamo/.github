# cocreiamo/.github

What the cocreiamo repositories share, written once: reusable workflows and the canonical copy of the shared rules.
Managed by cocreiamo/infrastructure (`tofu/github`).

## Reusable workflows

| Workflow | What it checks | Call it |
|---|---|---|
| `pr-title.yml` | the PR title (the squash commit on main) is a Conventional Commit and not a `test:` | `jobs: {title: {uses: cocreiamo/.github/.github/workflows/pr-title.yml@<sha>}}` on `pull_request` `[opened, edited, synchronize, reopened]` |
| `shared-rules.yml` | `CLAUDE.md` carries, byte for byte, the section `## Working with the founder` of `shared/working-with-the-founder.md`, and every script the repository declares in `.github/shared-scripts` is a copy of the canonical one in `shared/scripts/` (content and executable bit) | `jobs: {rules: {permissions: {contents: read}, uses: cocreiamo/.github/.github/workflows/shared-rules.yml@<sha>}}` on `pull_request` `[opened, synchronize, reopened]` |
| `post-merge-revert.yml` | not a check: after a merge to main, when a required job failed on the merge commit, opens `revert: <title>` through GitHub's `revertPullRequest` (auto-merge on, made by the App `cocreiamo-claude-code-pr`), comments on the original PR and raises an issue `main is red` (label `main-red`, assigned to the founder). The commit it reverts is the first red of the contiguous red streak on main (the walk goes back through first parents until a green run; a cancelled, skipped or unfinished run is unknown, never green; a commit with no run is stepped over): a later red commit only alerts, and a streak that begins at an unknown run alerts and repeats that run. Never reverts a revert, a bot PR, a commit with no PR, or while main is green at its head (an open revert is closed by `post-merge-green.yml`); an alert issue of the same title is reused. With `retry: true` the first attempt only alerts and the attempt started by `post-merge-retry.yml` decides; `dry-run: true` writes nothing, and with `ignore-head-green: true` it does not stop at a green main but decides as if the commit were red (the monthly drill); a real run ignores that input | a job `post-merge` with `needs: [<required jobs>]`, `if: always() && github.event_name == 'push' && contains(needs.*.result, 'failure')`, `permissions: {}`, `uses: cocreiamo/.github/.github/workflows/post-merge-revert.yml@<sha>`, inputs `failed` and `app-id`, secret `app-private-key` |
| `post-merge-retry.yml` | not a check: GitHub refuses to rerun a run from inside itself, so a `workflow_run` workflow of the caller (`workflows: [<check>]`, `types: [completed]`, `branches: [main]`, `if` event push, conclusion failure, `run_attempt == 1`) repeats the failed jobs of a red run once; the caller's `post-merge` passes `retry: true` so a transient failure never reverts anything | a job `retry` with `permissions: {actions: write}`, `uses: cocreiamo/.github/.github/workflows/post-merge-retry.yml@<sha>`, input `run-id` |
| `post-merge-green.yml` | not a check: after a green run on main, closes every revert PR that `post-merge-revert.yml` opened (marker `post-merge-revert:<sha>`) for a red commit the green commit descends from: auto-merge off, a comment naming the green commit, the linked `main is red` issue closed; every other open `main is red` issue the revert workflow raised (body starting «The required job(s)») is closed too, when the green commit is its red commit or descends from it (the alert of a job that is never reverted stays open). A green commit older than the red one, or on another line, closes nothing; a failure raises the alert. `dry-run: true` writes nothing | a job `post-merge-green` with `needs: [<required jobs>]`, `if: always() && github.event_name == 'push' && !contains(needs.*.result, 'failure') && !contains(needs.*.result, 'cancelled')`, `permissions: {actions: read}`, `uses: cocreiamo/.github/.github/workflows/post-merge-green.yml@<sha>`, input `app-id`, secret `app-private-key` |
| `post-merge-alert.yml` | not a check: after a push to main, when a job that is never reverted failed (a `publish`: Harbor, Trivy, signing, registry), opens the issue `main is red: <job> failed` (label `main-red`, assigned to the founder) with the run link and the failing lines of the job log, one per failing job: while one is open, a repeat failure comments on it. Never reverts anything; `dry-run: true` writes nothing | a job `post-publish` with `needs: [<job>]`, `if: always() && github.event_name == 'push' && needs.<job>.result == 'failure'`, `permissions: {actions: read}`, `uses: cocreiamo/.github/.github/workflows/post-merge-alert.yml@<sha>`, inputs `failed` and `app-id`, secret `app-private-key` |

`alert-drill.yml` proves `post-merge-alert.yml` on a real run, by itself on the 1st of every month at 06:00 UTC and on demand (`gh workflow run alert-drill.yml`, whole cycle; `-f expect=created` or `-f expect=commented` runs one half): it fails a job on purpose, the alert opens an issue (title prefix `drill: `, label `drill`), `alert-drill-verify.yml` checks through the API that it carries the marker and the run link, the alert fires again and must comment, the verification reads the comment, comments «drill passed» and closes the issue. Before all that the drill closes any open `drill` issue an earlier failed run left (comment «closed by the next drill run <link>»; never a `main-red` issue, never a deletion; skipped by `expect=commented`, which needs the open one). A red scheduled drill raises `main is red: <job> failed` through the real alert, so a broken alert path reaches the founder. `title-prefix` and `label` are the inputs of the alert that keep a drill apart from a red main.

`bash tests/claude-telemetry.sh` proves that `.claude/settings.json` sends Claude Code telemetry to `otel.cocreiamo.com` (this repository sets it like the others).

Callers pin a commit SHA; Renovate proposes the bumps (see «Renovate»). `hooks/check-conflict-markers` (the pre-commit hook, set as `core.hooksPath` by mise, and a step of `check`) refuses a line starting with `<<<<<<<` or `>>>>>>>`; `bash tests/conflict-markers.sh` proves it on conflicted and clean files. `bash tests/pr-title.sh` proves the title check on good and bad titles, `bash tests/shared-rules.sh` the shared-rules check on a canonical, a diverged and a missing section, `bash tests/post-merge-revert.sh` the revert decision (first red of a streak, the replay of green, cancelled, red, red, the retry modes) and the whole flow against a fake API (dry run included), `bash tests/post-merge-retry.sh` the repeat of a red first attempt, `bash tests/post-merge-green.sh` the closing of reverts a green main outlived (older green commit, other line, no marker, auto-merge already off, a failure alerts), `bash tests/post-merge-alert.sh` the alert flow against a fake API (one issue per failing job, a comment on a repeat, clean failing lines, an unreadable log).

`.github/PULL_REQUEST_TEMPLATE.md` is the organization's default pull request template (a repository without its own gets it): what, why, the test proven red, how the class is closed; `bash tests/pr-template.sh` keeps the four sections.

## Shared rules

`shared/working-with-the-founder.md` is the one canonical copy of the section `## Working with the founder`, present in the `CLAUDE.md` of infrastructure, deploy and cocreiamo. A caller's token cannot read this private repository's files, so `shared-rules.yml` embeds the text and `tests/shared-rules.sh` keeps the embedded copy equal to the file. To change the rule: edit both here (the test fails otherwise), merge, then in each repository bump the pin of `shared-rules.yml` and carry the new text into its `CLAUDE.md`: until it does, its `rules / check` is red and the merge is blocked. Every caller must grant its job the permission the workflow needs (`pr-title.yml`: `pull-requests: read`; `shared-rules.yml`: `contents: read`), or the run is a `startup_failure`; each repository's checks require it.

## Shared scripts

Scripts that more than one repository needs have one canonical copy in `shared/scripts/` (flat names). Each repository keeps a vendored copy at its own path (it must work offline and the CI never fetches at runtime) and declares it in `.github/shared-scripts`, one `canonical-name local-path` per line (`#` comments; a script a repository deliberately does not share is listed there as a comment with the reason). `shared-rules.yml` carries the whole directory as a base64 gzipped tar (a caller's token cannot read this repository's files) and its check fails, printing the diff, when a declared copy differs, is missing or lost its executable bit, or when the manifest is absent, empty or names a script that is not canonical.

To change a script: edit `shared/scripts/<name>`, run `tools/embed-scripts.sh` (`tests/shared-scripts.sh` fails until the bundle matches), merge, then bump the pin in each repository: the Renovate postUpgradeTask (`renovate/sync-founder-section.sh`, the one command every caller allows) overwrites the declared copies with the canonical ones, so the bump PR is complete. `eol_check.py` is the end-of-life check every repository runs in its own scheduled CI (`mise run check:eol`: pinned mise tools, charts, image tags and FROM lines against endoflife.date, failing within 60 days of an end of life; run through `uv`, pyyaml pinned in the script); `bash tests/eol-check.sh` tests it. `workflow-tools-check.py` (with `hermetic_tools.py`, the lexer and the list of what every runner has, both vendored) refuses a `run:` step of a workflow that calls a tool the runner image lacks, unless an earlier step of the job installs it (`ci-mise-setup`, `mise install`, `mise x`, a setup action) and `mise.toml` pins it; `bash tests/workflow-tools.sh` proves it with `workflow-tools-test`, and `check` runs it on this repository's workflows. `workflow-hygiene-check.py` refuses a job with no `timeout-minutes`, a push-workflow concurrency group keyed on the ref alone and a `uses:` SHA that is an annotated tag object (not a commit); `bash tests/workflow-hygiene.sh` proves each rule red. `mktemp-trap-check` refuses a shell script that calls `mktemp` without an `EXIT` trap that removes what it made (leaked `tmp.*` directories fill a disk); allowlist `.github/mktemp-trap-allowlist`, lines `<path> <reason>`; `bash tests/mktemp-trap.sh` proves it. `heavy-lock` also refuses (exit 75) below `HEAVY_LOCK_MIN_FREE_GB` (10) free on the temp dir or the working directory. `bash tests/shared-scripts.sh` proves the check on identical, diverged, missing, non-executable and undeclared copies; `bash tests/sync-founder-section.sh` proves the sync.

`testlib.sh` is the library every test sources (`. "$(dirname "$0")/<path>/testlib.sh"`, a vendored copy wherever `.github/shared-scripts` puts it): `fail <message>`, `tmpdir` (sets `$tmp`, removed at exit), `stub_bin <name> [body]` (a stub first on `PATH`) `git_env_clear` (unsets `git rev-parse --local-env-vars`), `git_repo <dir>` (a throwaway repository on `main` with the identity `t@example.invalid` and signing off in its own config only) and `fake_gh` with `fake_gh_route <path> <json>` (a `gh` that answers `gh api <path>` from canned JSON, logs to `$FAKE_GH_LOG` and fails on anything else); `bash tests/testlib.sh` proves it.

`commit-identity` is the pre-commit hook script that refuses a commit whose author or committer email (`git var`) is on a reserved test domain (`example`, `*.example`, `example.*`, `invalid`, `*.invalid`, `test`, `*.test`, `localhost`, `*.localhost`): GitHub cannot attribute such a commit and its unattributed-changes rule blocks the PR (`bash tests/commit-identity.sh`). `git-env-cleared <dir|file>...` (from the repository root) refuses a shell script that runs `git init` or `git worktree add` without clearing `git rev-parse --local-env-vars` (or calling `git_env_clear`, or sourcing a `hermetic-git.sh`); it skips the vendored copies of `.github/shared-scripts`, comments and untracked files, and a script that drives its own repository on purpose carries `# git-env-cleared: allow <reason>` (`bash tests/git-env-cleared.sh`). `lint-baseline [shell|python|yaml|secrets|all|--fast]` runs shellcheck and shfmt, ruff check and format, `yamllint --strict` and gitleaks on the tracked files, minus the vendored copies and `tests/*/bad|good` fixtures; the strictness is the repository's own config (`.shellcheckrc`, `.editorconfig`, ruff, `.yamllint`, `.gitleaks.toml`) and `--list shell|python` prints what a part checks (`bash tests/lint-baseline.sh`). `mise-tools.toml` is the tools block every repository pins the same (shellcheck, shfmt, ruff, yamllint, gitleaks, typos, editorconfig-checker, actionlint, zizmor, yq, jq, uv; python stays in each repository): vendor it as `.config/mise/conf.d/shared-tools.toml`, which mise loads before the repository's own `mise.toml` (so the repository's pin wins and a tool only it needs stays there); a repository that pins a tool of the block pins the same version, `eol_check.py` and `workflow-tools-check.py` read the fragment too (`bash tests/mise-tools.sh`).

`wt-gc` and `wt-list` are this repository's own `mise run wt:gc [-- --dry-run]` and `mise run wt:list` (tasks in `mise.toml` that run the canonical scripts, so there is no second copy); `bash tests/worktrees.sh` proves them with `worktrees-test`. `pr-wait.sh` is `mise run pr:wait` (required checks at 60 s polls, slept through a GitHub rate limit; exit 0 only when merged, 75 pending: repeat in the foreground) in every repository, `pr-wait-test` its test and `gh-watch-interval.sh` the check that no file watches with `gh` faster than 60 s; `bash tests/pr-wait.sh` runs both.

`pins-consistent` refuses a repository that references `cocreiamo/.github`, or `actions/checkout`, `re-actors/alls-green` or `renovatebot/github-action`, at more than one ref across its workflows and composite actions (the refs and files are named); the shared Renovate preset groups every `cocreiamo/.github` ref of a repository in one PR (group `cocreiamo/.github pin`) so a bump never leaves two. `bash tests/pins-consistent.sh` proves it on fixtures and runs it here.

`stalled_prs.py` (with `stalled_prs_test.py`) and the reusable `stalled-prs.yml` raise the nightly issue `stalled pull requests` of a repository (a pull request open over 6 hours with a conflict, a red or no check, auto-merge off, or green and not merging): the workflow carries the script (`tools/embed-scripts.sh` embeds it; a caller's token cannot read this repository), inputs `cleanup` (empty the runner workspace first, default false) and `alert` (default true: a failed run raises `main is red: stalled failed`), optional secret `app-private-key` (the alert's); the caller job grants `contents: read`, `issues: write`, `pull-requests: read`, `checks: read` and `actions: read`; `bash tests/stalled-prs.sh` proves it.

`workflow-pins-check.py` refuses a caller of a reusable workflow in another repository whose `with:` or `secrets:` the workflow does not declare at the commit the caller pins, or that omits a required input or secret (actionlint checks only the local `./` calls; a mismatch in a remote call otherwise fails at startup on main). It reads each pinned file once (cache `~/.cache/workflow-pins`, then the contents API with `GH_TOKEN`, `GITHUB_TOKEN` or `gh auth token`; a private callee needs a token that can read it: in this repository `github.token`, elsewhere an App token for `cocreiamo/.github`), never the callee's main. `mise run ci` of every repository runs it; `workflow-pins-test` proves it (`bash tests/workflow-pins.sh`).

## Shared configs

`shared/config/` holds the one copy of the `.gitignore` (stored as `gitignore`, so it does not act on this directory) and of the linter configs every repository uses as they are, with no per-repository addition: `.editorconfig`, `.yamllint.yaml`, `ruff.toml`, `.shellcheckrc`, `.gitleaks.toml`, `.typos.toml`, `.markdownlint-cli2.yaml`, `.prettierrc.json`, `.hadolint.yaml`, `.vale.ini` and the Vale styles. Each started from the strictest version among the repositories; where two disagreed the stricter one won (ruff `line-length` 140 with E501 enforced, the shellcheck `disable=SC1091` dropped), and path-specific lists (ignores, excludes, allowlists) are the union of all of them. The `.gitignore` is the union of what the repositories ignored plus what the adopted tools generate. A repository declares what it vendors in `.github/shared-configs`, one `canonical-name local-path` per line (`gitignore .gitignore`, `.vale/styles/Cocreiamo/Banned.yml .vale/styles/Cocreiamo/Banned.yml`); `shared-rules.yml` carries `shared/config` as a second base64 gzipped tar (`tools/embed-scripts.sh` writes both) and its check fails, printing the diff, when a declared copy differs, is missing, is a link or names a config that is not canonical. A repository with no manifest is not checked yet. The Renovate postUpgradeTask overwrites the declared copies on a bump of the pin. `bash tests/shared-configs.sh` proves the check and the sync, `bash tests/shared-config-content.sh` the content (what the `.gitignore` ignores and must not hide, the rules each config keeps).

## Community health files

`.github/SECURITY.md` and `.github/ISSUE_TEMPLATE/` (forms `bug.yml` and `task.yml`, `config.yml`) join the pull request template as the organization defaults: GitHub reads them from the `.github/` folder of this repository for every repository that has none of its own. GitHub requires the `.github` repository to be public for defaults to apply; this one is private, so they take effect only once it is made public. `bash tests/community-files.sh` keeps the files valid and the founder's address the only contact.

## Renovate

Dependency updates are one self-hosted Renovate per repository: a nightly caller of the reusable `renovate.yml` (inputs `repositories`: extra repositories the token must reach; `extra-env`: JSON object of extra `RENOVATE_` variables, never one the workflow sets itself; `alert`, default true: a failed run opens `main is red: renovate failed`; secrets `app-private-key` required, `extra-env-secret` optional for secret values such as `RENOVATE_HOST_RULES`; the caller job grants `contents: read` and `actions: read`; this repository's caller is `renovate-nightly.yml`; `bash tests/renovate-reusable.sh` proves the contract) on the `[self-hosted, cocreiamo-ci]` runners, authenticated as the existing GitHub App `cocreiamo-claude-code-pr` (repository variable `CLAUDE_CODE_PR_APP_ID`, repository secret `CLAUDE_CODE_PR_APP_PRIVATE_KEY`; the key is in the SOPS file of cocreiamo/infrastructure as `CLAUDE_CODE_PR_APP_PRIVATE_KEY` and in the offline seed). Each repository's `renovate.json` extends `github>cocreiamo/.github` (the root `default.json`) and names its managers.

`default.json` at the root is the shared preset (`renovate/default.json` only points at it, for repositories that still extend the old path): `config:recommended`, action digests pinned, semantic commit titles that pass `pr-title.yml` (`ci(deps)` actions, `build(deps)` providers and mise tools, `chore(deps)` the rest), platform automerge of minor, patch and digest updates once the required checks are green, the dependency dashboard, and one group each for actions, providers and mise tools. A bump of the pin of `shared-rules.yml` merges by itself, and its `postUpgradeTasks` runs `renovate/sync-founder-section.sh` (fetched at the new pin) to rewrite the repository's `CLAUDE.md` founder section to the canonical text, so `rules / check` passes on the bump PR. The only command a Renovate run may execute is the one in `renovate/allowed-commands.regex`, set as `RENOVATE_ALLOWED_COMMANDS` in each `renovate.yml`. `bash tests/renovate-config.sh` validates the configs strictly (`renovate-config-validator`, pinned in `mise.toml`) and proves an invalid one is refused; `bash tests/sync-founder-section.sh` proves the sync.
