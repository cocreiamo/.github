What the cocreiamo repositories share, written once: reusable workflows and the canonical copy of the shared rules.

`alert-drill.yml` proves `post-merge-alert.yml` on a real run, by itself on the 1st of every month at 06:00 UTC and on demand (`gh workflow run alert-drill.yml`, whole cycle; `-f expect=created` or `-f expect=commented` runs one half): it fails a job on purpose, the alert opens an issue (title prefix `drill: `, label `drill`), `alert-drill-verify.yml` checks through the API that it carries the marker and the run link, the alert fires again and must comment, the verification reads the comment, comments «drill passed» and closes the issue. Before all that the drill closes any open `drill` issue an earlier failed run left (comment «closed by the next drill run <link>»; never a `main-red` issue, never a deletion; skipped by `expect=commented`, which needs the open one). A red scheduled drill raises `main is red: <job> failed` through the real alert, so a broken alert path reaches the founder. `title-prefix` and `label` are the inputs of the alert that keep a drill apart from a red main.

Callers pin a commit SHA; Renovate proposes the bumps (see «Renovate»). The hooks are the pre-commit framework's, as in every repository (`.pre-commit-config.yaml`, installed by mise's postinstall: `pre-commit install`; `hooks-check` refuses a repository without the shared hooks `conflict-markers`, `commit-identity` and `ci-prepush`, a `core.hooksPath`, or an installed hook the framework did not write, and `bash tests/hooks.sh` proves it and checks this config). The pre-commit hook and `mise run ci -- lint` run the shared `conflict-markers`, which every repository vendors: it refuses a line starting with `<<<<<<<` or `>>>>>>>` in tracked and untracked files, except under a directory of `.github/conflict-markers-allowlist` (`<path>/ <reason>`); `conflict-markers-test` (`bash tests/conflict-markers.sh`) proves it on conflicted and clean files and on the allowlist. `bash tests/pr-title.sh` proves the title check on good and bad titles, `bash tests/shared-rules.sh` the shared-rules check on a canonical, a diverged and a missing section, `bash tests/post-merge-revert.sh` the revert decision (first red of a streak, the replay of green, cancelled, red, red, the retry modes) and the whole flow against a fake API (dry run included), `bash tests/post-merge-retry.sh` the repeat of a red first attempt, `bash tests/post-merge-green.sh` the closing of reverts a green main outlived (older green commit, other line, no marker, auto-merge already off, a failure alerts), `bash tests/post-merge-alert.sh` the alert flow against a fake API (one issue per failing job, a comment on a repeat, clean failing lines, an unreadable log).

`.github/PULL_REQUEST_TEMPLATE.md` is the organization's default pull request template (a repository without its own gets it): what, why, the test proven red, how the class is closed; `bash tests/pr-template.sh` keeps the four sections.

## Commons release

This repository is public. `shared/scripts`, `shared/config` and the founder section are published as one versioned release (`release.yml`): the archive `commons-<version>.tar.gz` (`scripts/` without the tests of the scripts, `config/`, `founder-section.md`, `VERSION`), `SHA256SUMS`, and a build provenance attestation (`actions/attest-build-provenance`; attestations need a public repository, so a private one releases nothing). On every push to main that changes `shared/` or `tools/build-release.sh`, `tools/next-version.sh` picks the version from the Conventional Commit title of the squash commit (`feat` minor, `type!:` or a `BREAKING CHANGE` footer major, anything else patch; first release 1.0.0) and publishes it; `gh workflow run release.yml` releases the current main when nothing was published yet.

A consumer installs it with mise, one line pinned by version (Renovate bumps it; the `github:` backend verifies the attestation, and a `mise.lock` records the checksum):

```toml
[tools."github:cocreiamo/.github"]
version = "1.0.0"
asset_pattern = "commons-*.tar.gz"
bin_path = "scripts"
```

`bin_path` puts every script of `scripts/` on `PATH` (`wt-gc`, `pr-wait.sh`, `lint-baseline`, `workflow-pins-check.py`, ...), so a mise task is `run = "wt-gc"` and a workflow step after the mise setup calls them by name. The files stay in the mise install directory (`mise where github:cocreiamo/.github`, read-only cache, never committed). What a repository must hold at its own root (the `.gitignore`, the linter configs, the community files) is declared in `.github/shared-configs` (`<name in config/> <path here>`, `#` comments) and materialised by `commons-sync`: `mise run commons:sync` rewrites the copies and the `## Working with the founder` section of `CLAUDE.md`, `commons-sync --check` (the CI step) writes nothing and fails with the diff on any drift: content, a link in place of a copy, the executable bit, the section. Its tasks:

```toml
[tasks."commons:sync"]
run = "commons-sync"
[tasks."commons:check"]
run = "commons-sync --check"
```

`bash tests/commons-release.sh` proves it on a throwaway consumer: a reproducible archive without tests, the version rules, an install at the pinned checksum (a wrong one refused), the scripts on `PATH`, and `commons-sync` with each drift refused.

## Shared rules

`shared/working-with-the-founder.md` is the one canonical copy of the section `## Working with the founder`, present in the `CLAUDE.md` of infrastructure, deploy and cocreiamo. A caller's token cannot read this private repository's files, so `shared-rules.yml` embeds the text (`tools/embed-scripts.sh` writes it) and `tests/shared-rules.sh` keeps the embedded copy equal to the file. To change the rule: edit the file and run `tools/embed-scripts.sh` (the test fails otherwise), merge, then in each repository bump the pin of `shared-rules.yml` and carry the new text into its `CLAUDE.md`: until it does, its `rules / check` is red and the merge is blocked. Every caller must grant its job the permission the workflow needs (`pr-title.yml`: `pull-requests: read`; `shared-rules.yml`: `contents: read`), or the run is a `startup_failure`; each repository's checks require it.

## Shared scripts

Scripts that more than one repository needs have one canonical copy in `shared/scripts/` (flat names). Each repository keeps a vendored copy at its own path (it must work offline and the CI never fetches at runtime) and declares it in `.github/shared-scripts`, one `canonical-name local-path` per line (`#` comments; a script a repository deliberately does not share is listed there as a comment with the reason). `shared-rules.yml` carries the whole directory as a base64 gzipped tar in a here-document of its run script (a caller's token cannot read this repository's files; an env value would hit the kernel's 131072-byte cap on one variable, which `workflow-hygiene-check.py` now refuses) and its check fails, printing the diff, when a declared copy differs, is missing or lost its executable bit, or when the manifest is absent, empty or names a script that is not canonical.

To change a script: edit `shared/scripts/<name>`, run `tools/embed-scripts.sh` (`tests/shared-scripts.sh` fails until the bundle matches), merge, then bump the pin in each repository: the Renovate postUpgradeTask (`renovate/sync-founder-section.sh`, the one command every caller allows) overwrites the declared copies with the canonical ones, so the bump PR is complete. `eol_check.py` is the end-of-life check every repository runs in its own scheduled CI (`mise run check:eol`: pinned mise tools, charts, image tags and FROM lines against endoflife.date, failing within 60 days of an end of life; run through `uv`, pyyaml pinned in the script); `bash tests/eol-check.sh` tests it. `workflow-tools-check.py` (with `hermetic_tools.py`, the lexer and the list of what every runner has, both vendored) refuses a `run:` step of a workflow that calls a tool the runner image lacks, unless an earlier step of the job installs it (`ci-mise-setup`, `mise install`, `mise x`, a setup action) and `mise.toml` pins it; `bash tests/workflow-tools.sh` proves it with `workflow-tools-test`, and `check` runs it on this repository's workflows. `workflow-hygiene-check.py` refuses a job with no `timeout-minutes`, a push-workflow concurrency group keyed on the ref alone and a `uses:` SHA that is an annotated tag object (not a commit); `bash tests/workflow-hygiene.sh` proves each rule red. `mktemp-trap-check` refuses a shell script that calls `mktemp` without an `EXIT` trap that removes what it made (leaked `tmp.*` directories fill a disk), and a Python file whose `tempfile.mkdtemp`, `mkstemp` or `NamedTemporaryFile(delete=False)` is not removed in a `finally:` of the same function, the `tearDown`/`__exit__` of its class, or through `atexit`, `weakref.finalize` or `addCleanup` (fixtures under `tests/*/bad|good` are skipped); allowlist `.github/mktemp-trap-allowlist`, lines `<path> <reason>`; `bash tests/mktemp-trap.sh` proves it. `python-isolated-check` refuses a `python`/`python3` call in a shell script, a workflow `run:` or a mise task `run` without `-I` (or `-P`, which keeps an explicit `PYTHONPATH`) or `uv run --script`: the working directory or the script's directory first on `sys.path` lets a planted `json.py` run on `import json`; a line may carry `# python-isolated: allow <reason>`, shebangs are not calls, and `bash tests/python-isolated.sh` proves it. `heavy-lock` also refuses (exit 75) below `HEAVY_LOCK_MIN_FREE_GB` (10) free on the temp dir or the working directory. `mark_conflicts.py` (with `mark_conflicts_test.py`) is `dirty-prs.yml`'s script; `bash tests/maintenance-reusables.sh` proves `dirty-prs.yml`, `auto-merge-rearm.yml` and `eol.yml` (structure, the embedded script, behaviour on a stub API). `bash tests/shared-scripts.sh` proves the check on identical, diverged, missing, non-executable and undeclared copies; `bash tests/sync-founder-section.sh` proves the sync.

A check that greps for a forbidden pattern must fail when grep itself fails: `grep ... || true` and `xargs grep` read an argument list over ARG_MAX, an unreadable file or a bad pattern as «no match», and the check then passes on files it never read. `tools/grep-errors-check` refuses those forms in `shared/scripts`, `tests`, `hooks` and `tools` (the safe ones are `|| [ $? -eq 1 ]` and a NUL list through `xargs -0` with a wrapper that fails on exit 2, as `grep_files` in `gh-watch-interval.sh`); `bash tests/grep-errors.sh` proves each pattern-scanning shared script red on a tree larger than ARG_MAX whose last-sorted file holds the forbidden form, and on an unreadable file, and the refusal on a fixture of each unsafe form.

`testlib.sh` is the library every test sources (`. "$(dirname "$0")/<path>/testlib.sh"`, a vendored copy wherever `.github/shared-scripts` puts it): `fail <message>`, `tmpdir` (sets `$tmp`, removed at exit), `stub_bin <name> [body]` (a stub first on `PATH`) `git_env_clear` (unsets `git rev-parse --local-env-vars`), `git_repo <dir>` (a throwaway repository on `main` with the identity `t@example.invalid` and signing off in its own config only) and `fake_gh` with `fake_gh_route <path> <json>` (a `gh` that answers `gh api <path>` from canned JSON, logs to `$FAKE_GH_LOG` and fails on anything else); `bash tests/testlib.sh` proves it.

`commit-identity` is the pre-commit hook script that refuses a commit whose author or committer email (`git var`) is on a reserved test domain (`example`, `*.example`, `example.*`, `invalid`, `*.invalid`, `test`, `*.test`, `localhost`, `*.localhost`): GitHub cannot attribute such a commit and its unattributed-changes rule blocks the PR (`bash tests/commit-identity.sh`). `git-env-cleared <dir|file>...` (from the repository root) refuses a shell script that runs `git init` or `git worktree add` without clearing `git rev-parse --local-env-vars` (or calling `git_env_clear`, or sourcing a `hermetic-git.sh`); it skips the vendored copies of `.github/shared-scripts`, comments and untracked files, and a script that drives its own repository on purpose carries `# git-env-cleared: allow <reason>` (`bash tests/git-env-cleared.sh`). `lint-baseline [shell|python|yaml|format|secrets|all|--fast]` runs shellcheck and shfmt, ruff check and format, `yamllint --strict`, `prettier --check` (YAML, Markdown, JSON and JS: one formatter per file type, the rule of the founder section) and gitleaks on the tracked files, minus the vendored copies and `tests/*/bad|good` fixtures; the strictness is the repository's own config (`.shellcheckrc`, `.editorconfig`, ruff, `.yamllint`, `.prettierrc.json` and `.prettierignore`, `.gitleaks.toml`; this repository reads `shared/config/.prettierrc.json`) and `--list shell|python` prints what a part checks (`bash tests/lint-baseline.sh`). `mise-tools.toml` is the tools block every repository pins the same (shellcheck, shfmt, ruff, yamllint, gitleaks, typos, editorconfig-checker, actionlint, zizmor, yq, jq, uv, node, prettier; python stays in each repository): vendor it as `.config/mise/conf.d/shared-tools.toml`, which mise loads before the repository's own `mise.toml` (so the repository's pin wins and a tool only it needs stays there); a repository that pins a tool of the block pins the same version, `eol_check.py` and `workflow-tools-check.py` read the fragment too (`bash tests/mise-tools.sh`).

`wt-gc` and `wt-list` are this repository's own `mise run wt:gc [-- --dry-run]` and `mise run wt:list` (tasks in `mise.toml` that run the canonical scripts, so there is no second copy); `bash tests/worktrees.sh` proves them with `worktrees-test`. `mise run ci -- <part>` is the only definition of each check of this repository: a part is a mise task `ci:<part>` in `mise-tasks/ci/` that declares `sources`, and the pull request workflow calls exactly `mise run ci -- <part>`. `mise run ci -- affected` prints the parts the diff against the base needs (the workflow reads it to decide which steps run, `--github-output` for `fromJSON`), `mise run ci -- prepush` runs them (the `ci-prepush` pre-push hook, so a push never carries less than the CI checks; a clean tree that already passed them is not run again, so running it before `git push` does not make the hook run twice and `CI_PARTS_FORCE=1` runs it anyway), `mise run ci -- all` runs every part and `mise run ci -- check` refuses a part whose sources miss its own file, a `ci:` task `affected` can never select and a workflow that names a part that does not exist. `ci-parts` (shared/scripts, with `ci-parts-test`; `bash tests/ci-parts.sh`) is the script behind it and is the same in every repository; `workflow-hygiene-check.py` also refuses, in a repository with the task `ci`, a pull request workflow step that runs a check any other way (`bash tests/ci-parts.sh` and `bash tests/workflow-hygiene.sh` prove them). The parts here: `workflows` (actionlint, zizmor, pins, tools, hygiene), `lint` (conflict markers, git environment, secrets, mktemp, containers) and `tests` (every `tests/*.sh`, found by glob).

`harbor-retry`, `image-scan` and `image-sign` are the publish's registry scripts, vendored side by side (the monorepo's `tools/shared`): `image-scan` applies Harbor's prevent_vul policy with the pinned Trivy before a push, `image-sign` signs keyless and attaches the CycloneDX SBOM and the SLSA provenance (`image-sign verify` tells an image already published and signed), and every registry call goes through `harbor-retry`, which waits for a pending scan and retries a transient failure but never a verdict or a refusal; `bash tests/harbor-retry.sh` runs `harbor-retry-test`, `image-scan-test` and `image-sign-test` on stub commands (the retry policy, the critical gate and the resolved layout copy, the signature with both attestations and the provenance of the run). `image-registry-check` refuses a script, test or workflow that pulls straight from Docker Hub, ghcr.io, quay.io or registry.k8s.io (a docker statement, a keyed `image:`/`FROM` line, a quoted literal, or the shell or Python assignment of an image variable); roots in `.github/image-registry-paths`, allowlist `.github/image-registry-allowlist`, a line may carry `registry-ok: <why>`; `image-registry-test` carries the fixtures every repository shares (`bash tests/image-registry.sh`). `vex_lint.py` refuses an OpenVEX statement that silences a finding without a justification, an impact statement, a product or a vulnerability (`bash tests/vex.sh`, shared fixtures in `vex-test`). `pr-size` is the PR size gate: the changed lines of a pull request (binary files, lock files, the vendored copies and the reasoned globs of `.github/pr-size-ignore` not counted) over the budget (`PR_SIZE_BUDGET`, 400) are refused, unless the founder allows the PR to be large: the label `large-pr` or a `platform/*` integration branch pass with a warning. `comment-hygiene` refuses an added comment that cites a decision record, an issue or a pull request, tells history or keeps commented-out code (`--all` reads the whole tree; allowlist `.github/comment-hygiene-allowlist`, `<path> <reason>`; a line may carry `comment-hygiene: allow <reason>`). `shared-rules.yml` runs both on every pull request from the compare API (so callers add `labeled` and `unlabeled` to the trigger types); exit 0 only when merged, 75 pending: repeat in the foreground) in every repository, `pr-wait-test` its test and `gh-watch-interval.sh` the check that no file watches with `gh` faster than 60 s; `bash tests/pr-wait.sh` runs both.

`pins-consistent` refuses a repository that references `cocreiamo/.github`, or `actions/checkout`, `re-actors/alls-green` or `renovatebot/github-action`, at more than one ref across its workflows and composite actions (the refs and files are named); the shared Renovate preset groups every `cocreiamo/.github` ref of a repository in one PR (group `cocreiamo/.github pin`) so a bump never leaves two. `bash tests/pins-consistent.sh` proves it on fixtures and runs it here.

`stalled_prs.py` (with `stalled_prs_test.py`) and the reusable `stalled-prs.yml` raise the nightly issue `stalled pull requests` of a repository (a pull request open over 6 hours with a conflict, a red or no check, auto-merge off, or green and not merging): the workflow carries the script (`tools/embed-scripts.sh` embeds it; a caller's token cannot read this repository), inputs `cleanup` (empty the runner workspace first, default false) and `alert` (default true: a failed run raises `main is red: stalled failed`), optional secret `app-private-key` (the alert's); the caller job grants `contents: read`, `issues: write`, `pull-requests: read`, `checks: read` and `actions: read`; `bash tests/stalled-prs.sh` proves it.

`workflow-pins-check.py` refuses a caller of a reusable workflow in another repository whose `with:` or `secrets:` the workflow does not declare at the commit the caller pins, or that omits a required input or secret (actionlint checks only the local `./` calls; a mismatch in a remote call otherwise fails at startup on main). It reads each pinned file once (cache `~/.cache/workflow-pins`, then the contents API with `GH_TOKEN`, `GITHUB_TOKEN` or `gh auth token`; a private callee needs a token that can read it: in this repository `github.token`, elsewhere an App token for `cocreiamo/.github`), never the callee's main. `mise run ci` of every repository runs it; `workflow-pins-test` proves it (`bash tests/workflow-pins.sh`).

`claude-md-duplicates` keeps each rule in one place: `compare <repo>=<CLAUDE.md>...` refuses a paragraph or bullet longer than 120 characters that two repositories carry outside the shared section, or that repeats a rule of the shared section; a caller's `rules / check` cannot read the other private repositories, so `shared-rules.yml` runs `check <repo> CLAUDE.md shared/scripts/claude-md-paragraphs` against the fingerprints of the others, which `tools/claude-md-paragraphs <repo>=<checkout>...` rewrites from local checkouts whenever a repository changes a rule (then `tools/embed-scripts.sh`); `bash tests/claude-md-duplicates.sh` proves it.

## Shared configs

`shared/config/` holds the one copy of the `.gitignore` (stored as `gitignore`, so it does not act on this directory) and of the linter configs every repository uses as they are, with no per-repository addition: `.editorconfig`, `.yamllint.yaml`, `ruff.toml`, `.shellcheckrc`, `.gitleaks.toml`, `.typos.toml`, `.markdownlint-cli2.yaml`, `.prettierrc.json`, `.hadolint.yaml`, `.vale.ini` and the Vale styles. Each started from the strictest version among the repositories; where two disagreed the stricter one won (ruff `line-length` 140 with E501 enforced, the shellcheck `disable=SC1091` dropped), and path-specific lists (ignores, excludes, allowlists) are the union of all of them. The `.gitignore` is the union of what the repositories ignored plus what the adopted tools generate. A repository declares what it vendors in `.github/shared-configs`, one `canonical-name local-path` per line (`gitignore .gitignore`, `.vale/styles/Cocreiamo/Banned.yml .vale/styles/Cocreiamo/Banned.yml`); `shared-rules.yml` carries `shared/config` as a second base64 gzipped tar (`tools/embed-scripts.sh` writes both) and its check fails, printing the diff, when a declared copy differs, is missing, is a link or names a config that is not canonical. A repository with no manifest is not checked yet. The Renovate postUpgradeTask overwrites the declared copies on a bump of the pin. `bash tests/shared-configs.sh` proves the check and the sync, `bash tests/shared-config-content.sh` the content (what the `.gitignore` ignores and must not hide, the rules each config keeps).

## Renovate

Dependency updates are one self-hosted Renovate per repository: a nightly caller of the reusable `renovate.yml` (inputs `repositories`: extra repositories the token must reach; `extra-env`: JSON object of extra `RENOVATE_` variables, never one the workflow sets itself; `extra-allowed-commands`: JSON array of anchored regexes (`^...$`, refused when one allows an arbitrary command) of the commands a `postUpgradeTask` of the caller may run besides the founder-section sync (`RENOVATE_ALLOWED_COMMANDS` is written by the workflow from the sync command plus these; deploy passes `["^bash mise-tasks/vendor/upstream$"]`); `alert`, default true: a failed run opens `main is red: renovate failed`; Renovate exits 0 even when a repository run aborts, so the workflow reads each attempt's JSON log (`RENOVATE_LOG_FILE`): `repository-changed` (main moved during the run) is retried once, and any other non-zero result, or a run that never reached «Repository finished», turns the job red; secrets `app-private-key` required, `extra-env-secret` optional for secret values such as `RENOVATE_HOST_RULES`; the caller job grants `contents: read`, `actions: read` and `issues: write`; this repository's caller is `renovate-nightly.yml`; `bash tests/renovate-reusable.sh` proves the contract) on the `[self-hosted, cocreiamo-ci]` runners, authenticated as the existing GitHub App `cocreiamo-claude-code-pr` (repository variable `CLAUDE_CODE_PR_APP_ID`, repository secret `CLAUDE_CODE_PR_APP_PRIVATE_KEY`; the key is in the SOPS file of cocreiamo/infrastructure as `CLAUDE_CODE_PR_APP_PRIVATE_KEY` and in the offline seed). Each repository's `renovate.json` extends `github>cocreiamo/.github` (the root `default.json`) and names its managers.

`default.json` at the root is the shared preset (`renovate/default.json` only points at it, for repositories that still extend the old path): `config:recommended`, action digests pinned, semantic commit titles that pass `pr-title.yml` (`ci(deps)` actions, `build(deps)` providers and mise tools, `chore(deps)` the rest), platform automerge of minor, patch and digest updates once the required checks are green, the dependency dashboard, one group each for actions, providers and mise tools, a fixed window (`schedule` `* 1-6 * * *` Europe/Rome, around the 03:17 nightly run; only the `cocreiamo/.github` pin opens at any hour), and majors left as reviewed PRs with the changelog (`fetchChangeLogs: pr`); `osvVulnerabilityAlerts` (OSV needs no GitHub permission) and `vulnerabilityAlerts` make a security fix bypass the schedule and the release age. A bump of the pin of `shared-rules.yml` merges by itself, and its `postUpgradeTasks` runs `renovate/sync-founder-section.sh` (fetched at the new pin) to rewrite the repository's `CLAUDE.md` founder section to the canonical text, so `rules / check` passes on the bump PR. The only command a Renovate run may execute is the one in `renovate/allowed-commands.regex`, set as `RENOVATE_ALLOWED_COMMANDS` in each `renovate.yml`. `tools/schemas` (run by `ci:lint`, `check-jsonschema` pinned in `mise.toml`) validates the workflows, the issue forms and their config, and the Renovate configs against the SchemaStore schemas check-jsonschema vendors, offline; `bash tests/schemas.sh` proves each refused on a broken copy. `bash tests/renovate-config.sh` holds the preset to that regime (each rule proven red on a bad copy), validates the configs strictly (`renovate-config-validator`, pinned in `mise.toml`) and proves an invalid one is refused; `bash tests/sync-founder-section.sh` proves the sync.
